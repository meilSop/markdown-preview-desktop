在开始任务之前，阅读相关的开发指南。

执行以下步骤：

1. **阅读当前任务产物**：
   - `prd.md` 了解需求和验收标准
   - `design.md`（如存在）了解技术设计
   - `implement.md`（如存在）了解执行顺序和验证计划

2. **发现包及其规范层**：
   ```bash
   python ./.trellis/scripts/get_context.py --mode packages
   ```

3. **确定哪些规范适用于你的任务**，基于以下因素：
   - 你正在修改哪个包（例如 `cli/`、`docs-site/`）
   - 工作类型（后端、前端、单元测试、文档等）
   - 任务产物中引用的任何规范/研究路径

4. **阅读每个相关模块的规范索引**：
   ```bash
   cat .trellis/spec/<package>/<layer>/index.md
   ```
   遵循索引中的 **"Pre-Development Checklist"** 部分。

5. **阅读开发前检查清单中列出的具体指南文件**，选择与你的任务相关的文件。索引本身不是目标——它指向实际的指南文件（例如 `error-handling.md`、`conventions.md`、`mock-strategies.md`）。阅读这些文件以了解编码标准和模式。

6. **始终阅读共享指南**：
   ```bash
   cat .trellis/spec/guides/index.md
   ```

7. **对于非简单任务，在编写代码之前明确变更边界。** 非简单任务是指涉及多个文件、跨越多个层、更改公共接口、或编辑非刚编写代码的任务。写下以下内容：
   - 当前行为与期望行为之间最小的行为差距
   - 该行为实际存在的位置（而非最容易拦截的位置）
   - 你预期需要更改哪些文件，以及每个文件为什么是必要的
   - 你在此任务中明确不做什么
   - 如果需要局部重构，你将如何证明它没有改变行为

   小而范围明确的任务不需要这一步——直接执行即可。

   如果实际范围明显大于预期，在继续之前说明原因。不要自行扩大变更范围。

8. 理解你需要遵循的编码标准和模式，然后继续你的开发计划。

此步骤在编写任何代码之前是**强制性的**。
